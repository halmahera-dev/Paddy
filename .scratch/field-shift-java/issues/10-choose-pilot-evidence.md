# Choose the pilot evidence and partner

Type: `grilling`  
Status: resolved  
Parent: [Field Shift Java decision map](../map.md)
Blocked by: 04

## Question

Given the [pilot input contract](./04-pilot-input-contract.md), what partner access and independent check sample must a Java pilot have to test its comparisons and crop-history claims? Set a rule for choosing a district or farming zone based on checked plot boundaries, crop and irrigation records, soil measurements where available, crop details, and observed outcomes. Set a fallback if the needed validation records cannot be obtained. Do not require soil class or past crop history for every prospective screen, and do not choose a place only because it looks complete on the FTW map.

## Answer

No pilot partner is confirmed. **Partner data is a gate for the checked working proof**, not a reason to stop testing the NASA and FTW data path. Choose a Java zone because a partner can provide records that can be checked, not because its FTW map looks complete.

Before naming a zone as the **checked pilot**, obtain permission to use these records for the proof:

1. A dated zone boundary and a set of locally checked plot IDs and boundaries, with a clear rule for linking or rejecting FTW predictions.
2. Dated planting and harvest records with named crops for the plots used to show crop history. Record missing or recalled dates as uncertain; do not fill them from imagery.
3. Checked rainfed or irrigated status and known seasonal water limits for plots used in an irrigation result. Soil class and measurements are needed only for the results that use them.
4. An independent check set, kept out of any rule fitting, with actual crop dates or outcomes and local rain or irrigation observations where possible. The [rotation evidence standard](./12-set-rotation-evidence-standard.md) will set its size and success limits before validation claims are made.
5. A named reviewer from the partner or an agronomist who can check plot links, crop durations, and the local meaning of the result.

The gate passes when the team can trace these records to their source, dates, units and plots, and the reviewer accepts the links. A missing soil class or past crop history on an individual plot does not block a prospective calendar or crop-water screen; it blocks only the dependent result. A plot with no checked boundary cannot support a plot-level crop-history claim.

**Before the gate passes:** build an exploratory zone-level demonstration with real, dated NASA observations and FTW predictions. Use clearly marked example plans to test the calculation. Show crop names, local water facts, and plot histories only where checked records exist. Do not call the demonstration a checked pilot, a validated recommendation, or evidence of improvement over KATAM. Keep the first milestone open until the partner data gate passes.
